# Выравнивание нумерации стихов в bible.db (Tools/BibleAlign)

## Что это

В `Sources/bible.db` номера глав и стихов английские (так же сделано для Псалмов): стих N в любой колонке (`text_hy` эчмиадзинский 1895, `text_hy_ararat` Нор Арарат 2018, `text_ru` синодальный, `text_en` английский KJV) это стих N английской Библии.
До 2026-11-25 в 33 местах (39 глав) это было не так: тексты лежали на соседних номерах, в конце глав стояли строки на чужом языке. Из-за этого читалка, поиск, стих дня, игра «Собери стих» и ссылки от ИИ показывали не тот стих. Инструмент разложил тексты по английским номерам. Сами слова текстов не менялись (кроме шести стихов KJV, которых в английской колонке не было совсем).

Запуск: Node 22.13 или новее (встроенный `node:sqlite`; проверено на Node 26). Исходная база никогда не меняется, результат пишется в новый файл.

```bash
node Tools/BibleAlign/align.mjs report <исходная.db>                  # что будет сделано, без записи
node Tools/BibleAlign/align.mjs apply  <исходная.db> <новая.db> --review список.md
node Tools/BibleAlign/align.mjs check  <база.db>                      # чужой язык в колонках и участки со сдвигом, код выхода 1 если есть
```

`apply` работает только на базе с контрольной суммой, записанной в `spec.mjs` (`ORIGINAL_SHA256`, это база до правки), поэтому дважды правки не применить. Результат повторяем: одна и та же база даёт тот же файл.

## Как устроено

Таблица правок `spec.mjs`: для каждого места участок, операции над текстами колонки (`drop` убрать заглушку, `merge` склеить, `split` разрезать, `insert…` вставить, `moveToEnd`, `appendEmpty`) и строки, куда класть результат. Для эчмиадзинского чаще используется `partition`: тексты режутся по предложениям и раскладываются по строкам так, чтобы быть максимально похожими на тот же стих Нор Арарат (два армянских перевода сходятся по словам). Операции проверяют себя: убирается только заглушка (чужой язык, пусто, «см. предыдущий стих»), метка разреза должна встречаться ровно один раз, число кусков должно совпасть с числом строк, слова после раскладки те же.

После правок: удаление лишних строк, пересборка поиска (`verses_fts` rebuild и integrity-check), `VACUUM`, `integrity_check`, затем `check`.

`check` ищет остатки двумя способами и сам учится на базе: связи слов «русское или армянское слово ↔ английское» берутся из самих данных (почти везде номера совпадают, редкие сдвиги шумом не мешают). Плюс прямое сравнение двух армянских переводов. Ищет также строки на чужом языке и пустые.

## Что осталось и почему

`check` на исправленной базе проходит благодаря списку `KNOWN_EDGE` в `spec.mjs`:

- **Русский Даниил не исправлен.** В нём не хватает части стихов (например, синодальных Дан 2:15 и Дан 4:17: на их месте стояли армянские заглушки, пересборка 2026-10-20 их убрала), поэтому тексты стоят на соседних номерах. Починить можно только по синодальному тексту Даниила; в `ru_synod.json` его нет, нужен другой источник.
- Списки имён (Неем 10 и 12) и царей (Нав 12, 19): в Нор Арарат имена раскиданы по стихам иначе, число стихов то же; в эчмиадзинском Нав 19:36–37 и Откр 20:8–9 два соседних стиха делят предложения иначе, дальше всё сходится.
- Три стиха в Нор Арарат стоят как «...» (Лк 17:36, Деян 24:7, Деян 28:29): это стихи, которых нет в современном критическом тексте; так было и до правки.

## Проверка носителем армянского

`REVIEW_ARMENIAN.md`: каждое место склейки и разреза армянских стихов. Слова не менялись; в этих местах меняются знаки препинания и регистр первой буквы (после разреза первая часть оканчивается на «։», вторая начинается с заглавной; при склейке «։» первой части становится «.» в эчмиадзинском, а после запятой вторая часть пишется со строчной). Список нужно показать носителю до выпуска.

## Английские стихи, вписанные вручную

Шесть стихов KJV (`KJV` в `spec.mjs`) вписаны по общественному достоянию и сверены 2026-11-25 с публичным текстом KJV (biblegateway.com): орфография базы (`enquired`), курсив `{…}` не размечен (источника с курсивом не нашлось; на смысл текста это не влияет).

## При каждой замене bible.db

1. Скопировать новую базу в `Sources/bible.db` и `android_app/app/src/main/assets/bible.db` (файлы должны быть одинаковыми).
2. Поменять `ASSET_STAMP` в `android_app/.../BibleDatabaseHelper.kt`, иначе на Android у уже установивших останется старая база. iOS открывает базу прямо из пакета приложения, ему ничего менять не нужно.
3. Поисковый индекс пересобрать (`INSERT INTO verses_fts(verses_fts) VALUES('rebuild')`), базу сжать (`VACUUM`).
4. Прогнать `node Tools/BibleAlign/align.mjs check <база.db>`: он должен показать «найдено проблем: 0».

## Чего инструмент не меняет

Избранное и заметки в приложении хранят копию текста на момент сохранения (`FavoriteItem`, `VerseAnnotation`), поэтому сохранённое из сдвинутых мест само не исправится. Цветные выделения и заметки привязаны к номеру стиха: в местах, где номера поменялись, они окажутся на соседнем стихе.
